### 왜 전부 중앙 크롭인가

프레임을 뽑아 확인한 결과 코치·수강생 쌍이 대체로 x 680~1200 구간에 머뭅니다. 중앙 창(656~1264)이 그대로 덮습니다. 좌·우 프리셋을 쓸 구간은 선정된 5개 안에 없었습니다.

**제외한 구간:**
- 임팩트 위치 설명 (06:58~07:16) — 좋은 팁이지만 코치가 x≈400, 수강생이 x≈1030에 서서 둘 사이가 630px. 608 창에 둘이 안 들어갑니다. SPEC §4-4대로 제외.
- 준비 자세 (01:59~02:21) — 시작 시점(119~123초)에 두 사람이 x≈450 / x≈1425로 벌어져 있습니다. 124초부터 붙지만 그러면 "발은 어깨 넓이로"를 잃어 교습 포인트가 반쪽이 됩니다.

## 실행 기록 — 경로 B (자동) 로 진행됨

capcut-cli **0.18.0**으로 드래프트 5개를 자동 생성했습니다.

| 항목 | 결과 |
|---|---|
| 설치 | npm 미배포(최신 0.17.2 = 취약 버전) → GitHub 태그 `v0.18.0` 클론 후 빌드 |
| 캔버스 | 1080x1920 / 30fps / 9:16 — 5개 전부 확인 |
| 구간 | 원본 인점·길이 5개 전부 지시서와 일치 |
| 크롭 | `crop --rect 0.341667,0,0.316667,1` → 소스 x 656~1264px |
| 본문 자막 | 다듬은 SRT를 caption 트랙으로 삽입, `y=-0.6` |
| 훅 자막 | 별도 텍스트 트랙, 24pt `#FFE14D`, 0~1.5초, `y=0.55` |
| lint | 5개 전부 이슈 0 |

생성된 CapCut 프로젝트: `숏폼1_그립` `숏폼2_손목` `숏폼3_덮고사선` `숏폼4_오른쪽라인` `숏폼5_공의식`

### 실행 중 걸렸던 것

- **템플릿 스키마 불일치** — CLI 번들 템플릿이 CapCut 6.5.0 스키마, 설치된 앱은 7.3.0. 알려진 문제(issue #67)로 드래프트가 안 열릴 수 있음. 사용자가 만든 빈 프로젝트 `0812 (1)`을 `--template`으로 넘겨 해결.
- **앱 실행 중 쓰기 거부** — CLI 안전장치. `--force-write`를 쓰지 않고 캡컷을 종료한 뒤 진행.
- **ffmpeg에 `drawtext` 없음** — `capcut render --burn-captions` 미리보기는 못 씀. 캡컷에서 확인하는 데는 지장 없음.

### 남은 수동 작업

1. **내보내기** — macOS는 자동 export 미지원. 캡컷에서 각 프로젝트 열어 1080x1920으로 내보내 `output/clips/`에 저장
2. **단어별 색상 강조** — 클립별 강조 단어는 위 각 절 참고. 클립당 30초
