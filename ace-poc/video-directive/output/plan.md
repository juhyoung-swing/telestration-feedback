# 스포츠 강의 AI 자동 편집 파이프라인 기획서

버전: 1.0 (fresh start)
작성일: 2026-08-14
상태: 기술 검증(pre-MVP) 단계

---

## 1. 개요

무편집 스포츠 강의 원본 영상을 입력받아, AI가 편집 판단을 내리고 기계가 이를 실행하여 완성 영상을 출력하는 7단계 파이프라인.

핵심 설계 원칙은 세 가지다.

**판단과 실행의 분리.** 모든 편집 판단은 2단계에서 `통합 편집 지시서(JSON)` 하나로 확정된다. 3~6단계는 이 지시서를 기계적으로 실행할 뿐, 새로운 판단을 하지 않는다. 따라서 실행 단계는 결정론적이며, 결과에 문제가 있으면 지시서만 보면 원인을 추적할 수 있다.

**단일 좌표계.** 모든 시간 좌표는 처음부터 끝까지 원본 영상의 타임코드(초, float) 하나로 통일한다. 중간 산출물에서 물리적 삭제/재렌더를 하지 않으므로 좌표가 밀리지 않는다. 물리적 컷은 4단계에서 단 한 번 일어난다.

**무음 ≠ 삭제.** 스포츠 강의에서 가장 값진 구간은 말없이 보여주는 시범 동작이다. 오디오 기준으로는 무음이지만 절대 삭제되면 안 된다. 시각 패스(Gemini)가 이런 구간에 보호 마킹을 하며, 보호 마킹은 삭제 마킹보다 항상 우선한다. 이것이 범용 편집 도구(Descript 등)와 이 파이프라인의 근본적 차별점이다.

## 2. 7단계 파이프라인

### 1단계: 원석 정제 (Audio & Visual Data Fusion)

| 항목 | 내용 |
|---|---|
| Input | 무편집 원본 영상 (MP4/MOV/WebM) |
| 처리 (Audio) | Whisper — 전사(단어 단위 타임스탬프), 말더듬("어…", "음…"), NG 음성, 무음 구간 감지 |
| 처리 (Visual) | Gemini 3.6 Flash — 시선 이탈, 장비 정비 등 불필요 동작 감지 + **말없는 시범 동작 보호 마킹** |
| Output | `[Clean 대본 & 타임스탬프]` — 전사 + 제외 후보 목록 + 보호 구간 목록 |

역할 분리: Whisper는 귀, Gemini는 눈. Whisper는 단어 단위 정밀도가 필요한 오디오 검출을 전담하고, Gemini는 이미 확보된 전사를 텍스트로 함께 입력받아 시각 관찰에만 집중한다(음성 재인식에 자원을 쓰지 않게 함).

Gemini 타임스탬프는 1초 해상도임을 전제한다. 시각 이벤트의 경계는 ±1초 오차를 가질 수 있으며, 이는 4단계 HITL(컷 타이밍 미세 조정)에서 흡수한다.

### 2단계: 기획 (스토리라인 구축 및 통합 지시서 완성)

| 항목 | 내용 |
|---|---|
| Input | `[Clean 대본]` + 스포츠 강의 프롬프트 템플릿 |
| 처리 (LLM) | 강의 구성 순서 재배치(오프닝 → 핵심 포인트 → 요약 등), 필요 에셋(B-roll, CG, SFX) 목록 정의, 타임라인별 편집 지시서 작성 |
| Output | `[통합 편집 지시서 JSON]` — 별도 스키마 문서 참조 |

이 단계가 파이프라인의 척추다. 유일하게 창의적 판단이 개입하는 지점이며, 유일하게 새로 설계해야 하는 산출물(지시서 스키마)을 만든다. LLM은 지시서를 2~3안 생성하여 인간이 선택/수정하게 한다(단일안 수정보다 복수안 선택이 리뷰 비용이 낮음).

원본에 존재하지 않는 화면이 필요한 경우, 실패가 아니라 `need_shoot` / `need_create` 상태의 에셋 항목으로 기록된다. 이 목록은 그대로 추가 촬영 요청서가 된다.

### 3단계: Rough Cut (1차 정제 데이터)

| 항목 | 내용 |
|---|---|
| Input | 지시서 JSON |
| 처리 | 지시서의 storyline 구간과 exclusions(제외 목록)를 대조하여 충돌 검증, 최종 컷 리스트(EDL 데이터) 산출 |
| Output | 검증 완료된 영상 파이프라인 데이터 (렌더 아님) |

주의: 이 단계는 영상을 렌더링하지 않는다. 물리적 삭제를 먼저 수행하면 타임코드가 밀려 5~6단계의 오버레이 좌표가 전부 어긋난다. 3단계의 실체는 (1) storyline의 A-roll 구간이 exclusions와 겹치지 않는지, (2) protected 구간이 실수로 제외되지 않았는지 검증하는 lint 단계다.

### 4단계: A-roll 확정 (뼈대 완성)

| 항목 | 내용 |
|---|---|
| Input | 원본 영상 + 3단계 검증 완료 데이터 |
| 처리 | 지시서 storyline 순서대로 구간을 추출·연결하여 컷편집 완성. **물리적 컷은 여기서 단 한 번** |
| Output | `[A-roll 완성본]` |

### 5단계: B-roll 오버레이 (살 붙이기)

| 항목 | 내용 |
|---|---|
| Input | `[A-roll 완성본]` + B-roll 소스(클로즈업, 슬로우 모션, 인서트) |
| 처리 | 지시서 b_roll 항목대로 V2 트랙에 오버레이. A-roll 오디오 유지 |
| Output | `[B-roll 완성본]` |

B-roll 위치는 출력 타임라인의 절대 시각이 아니라 **블록 앵커(block_id + offset)** 로 지정한다. 4단계 HITL에서 컷 타이밍이 조정되어도 B-roll이 따라 움직이므로 좌표 재계산이 필요 없다.

### 6단계: 에셋 얹기 (자막, CG, 효과음)

| 항목 | 내용 |
|---|---|
| Input | `[B-roll 완성본]` + CG/자막/SFX 에셋 |
| 처리 | V3 트랙에 Whisper 기반 자막 + 강조 자막, 모션 CG(골반 회전 화살표, 관절 궤적 등), SFX 오디오 결합 |
| Output | `[에셋 합성 완성본]` |

자막 타이밍은 Whisper의 단어 단위 타임스탬프에서 직접 파생된다(1단계에서 Whisper를 쓰는 이유). CG 위치 역시 블록 앵커 방식.

### 7단계: 후반 마감 (Polish & Master)

| 항목 | 내용 |
|---|---|
| Input | `[에셋 합성 완성본]` |
| 처리 | 오디오 노이즈 제거, 음량 평준화(Loudness Normalization), 톤앤매너 색보정 LUT 일괄 적용 |
| Output | `[최종 완제품 MP4]` 또는 `[편집자 검수용 NLE 프로젝트 파일(XML)]` |

## 3. 휴먼 인 더 루프 (HITL)

| 게이트 | 위치 | 검수 대상 | 검수자 |
|---|---|---|---|
| G1 | 1~2단계 뒤 | AI 스토리라인 및 B-roll/에셋 지시서(JSON). 복수안 중 선택 + 수정 | 코치 (내용) / 개발자 (구조) |
| G2 | 4단계 뒤 | A-roll 컷 타이밍·호흡 미세 조정. Gemini 1초 해상도 오차 흡수 지점 | 편집 감각 있는 인원 |
| G3 | 6~7단계 뒤 | 자막 오탈자, CG 위치, 최종 색감 확인 후 렌더링 승인 | 코치 + 개발자 |

G1이 가장 중요하다. 지시서는 텍스트이므로 코치가 영상 도구 없이 읽고 승인할 수 있다. 코치의 리뷰 단위는 "대본과 구성"이며, 이는 코치가 원래 하던 일과 동일한 형태다.

## 4. 도구 스택

| 역할 | 도구 | 비고 |
|---|---|---|
| 오디오 전사·검출 | Whisper (로컬, M1 Pro) | 단어 단위 TC. API 비용 없음 |
| 시각 관찰 | Gemini 3.6 Flash | 영상 네이티브 입력. 1초 해상도. 3.7은 영상 이해 개선 근거 없음 + 미검증이라 보류 |
| 기획 LLM | Claude / Gemini | 텍스트 작업. 지시서 생성 |
| 컷·합성 실행 | ffmpeg / capcut-cli | 지시서 → 실행 |
| CG | SVG 규칙 기반 렌더링 | 생성형 아님. 재현 가능 |

Gemini 호출 시: 컨텍스트 캐싱 필수(같은 영상에 다중 질의), 요청당 영상 1개, 프롬프트는 영상 뒤 배치, `responseSchema`로 출력 구조 강제.

비용 참고: 8분 원본 기준 기본 해상도 약 14만 입력 토큰. Flash 단가에서 패스당 1달러 미만. 토큰 절약보다 스윙 구간 fps 상향에 예산을 쓰는 것이 옳은 트레이드.

## 5. 검증 계획 (데모 범위)

기존 확보 원본(8분 3초, 1920×1080, 60fps)으로 숏폼 1편을 이 파이프라인 전체를 통과시켜 산출한다. 신규 촬영 불필요.

성공 기준:
1. 1단계 출력에서 무음 시범 구간이 보호 마킹되어 살아남는가
2. 지시서 JSON만 보고 4~6단계가 사람 개입 없이 실행되는가
3. G2에서의 수동 조정량이 허용 범위(컷당 ±0.5초 이내 미세 조정 수준)인가
4. 코치가 G1에서 지시서를 영상 없이 텍스트만으로 리뷰 완료할 수 있는가

실패 시 학습 포인트: 어느 단계에서 지시서와 실행 결과가 어긋났는지 → 스키마 보강 대상 식별.

## 6. 리스크

| 리스크 | 완화 |
|---|---|
| Gemini 시각 패스 타임아웃 (Descript에서 동일 증상 관측됨) | 영상을 구간 분할하여 다중 요청. 컨텍스트 캐싱 |
| 시각 이벤트 경계 ±1초 오차 | G2에서 흡수. 스윙 순간 지목이 필요한 CG는 해당 구간만 고fps 재처리 |
| 한국어 스포츠 용어 오인식 | Whisper 프롬프트에 용어 사전(glossary) 주입. 1단계에서 1회만 관리 |
| 지시서 스키마 미비로 실행 단계가 임의 해석 | 스키마에 없는 상황 발견 시 실행 중단 + 스키마 보강. 실행 단계의 임의 판단 금지 |
