# Project ACE — 테니스 영상 자동 분석 POC

경기 영상 하나에서 **랠리 구분 · 타격 카운트 · 선수별 귀속 · 스윙 종류 · 낙구 지점**을
자동으로 뽑아낼 수 있는지 확인한 결과물입니다.

- 대상: `match_b.mp4` (강준수 vs 공지훈, 양구매치, 14분 30초) 중 **45~112초**
- 이 구간에 랠리 6개, 타격 44개
- 학습은 하지 않았습니다. 공개 가중치 + 직접 작성한 후처리로만 구성

## 2. 무엇이 되는가

| 항목 | 방법 | 검증 |
|---|---|---|
| 코트 좌표계 | 키포인트 14점 수동 보정 → 호모그래피 | 재투영 오차 **3.3 cm** |
| 랠리 구분 | 두 선수가 베이스라인 뒤에 **동시에 멈추는 시점** | 실제 서브 시점 **3/3 일치** |
| 타격 카운트 | **공-선수 최근접** (공이 라켓에 붙는 순간) | 17타 랠리에서 **17타** |

**소리를 쓰지 않습니다.** 랠리 구분과 타격 카운트 모두 영상만으로 판정하므로,
스코어보드가 없는 영상이나 직접 촬영한 영상에도 그대로 적용됩니다.
(낙구 계산의 구간 분할에만 오디오 onset을 보조로 사용)

## 3. 무엇이 안 되는가

**인/아웃 판정 · 서브 성공률 · 스트로크 속도는 넣지 않았습니다.**
신뢰할 수준으로 측정되지 않아 리포트에서 제외했습니다.

- **공 검출 71%** — 프레임 10장 중 3장은 공을 못 찾고 계산으로 메웁니다.
  특히 **타격 순간**에 공이 라켓·몸에 가려져, 건너편 선수(P2)는 그 순간 검출률이 **52%**까지 떨어집니다.
- **낙구 추적 48~52%** — 타격 44번 중 22번만 낙구를 알아냅니다. 지도의 점이 선수당 11개뿐인 이유입니다.
- **낙구 정확도** — 전수 검증(`evidence/bounce_verification.jpg`) 결과 절반 정도만 확실합니다.
- **스트로크 속도** — 공중의 공을 지면에 투영해 계산하므로 구조적으로 과대평가됩니다.
- **낮은 카메라 각도** — `court_keypoints_fail.jpg` 참고. 코트가 화면 세로의 13%로
  눌리면 코트 인식이 통째로 실패합니다(오차 92.8 cm).

---

## 4. 촬영 조건 (중요)

영상 3개를 같은 파이프라인에 넣어 비교한 결과, **카메라 높이가 성패를 가릅니다.**

| | 코트가 화면에서 차지하는 세로 비중 | 재투영 오차 | 판정 |
|---|---|---|---|
| match_b (실내, 높은 카메라) | 70% | 5.1 cm | 최적 |
| match_amateur (실외, 높은 카메라) | 54% | 6.7 cm | 충분 |
| match_c (실외, **낮은 카메라**) | 13% | 92.8 cm | **불가** |

> **코트가 화면 세로의 50% 이상을 차지하도록, 베이스라인 뒤 높은 위치에서 촬영할 것.**

추가로 **비트레이트를 20 Mbps 이상**으로 촬영하면 공 검출률이 오릅니다.
현재 소스는 2.44 Mbps이고, H.264는 비트가 모자라면 빠르게 움직이는 작은 물체부터 뭉갭니다.

