# 관리자 — 웹

**MVP 플랫폼: 웹.** 데스크톱 폭으로 그린다. 셋 중 유일하게 모바일이 아니다.

| | 문서 | 표기 |
|---|---|---|
| 지금 | [MVP 기획서 §6.2](../mvp-plan-v1.md:187) | **관리자 웹** |
| 장기 | [제품정의서 §6.1](../product-definition-v1.md:180) | "**웹을 기본 관리도구로** 제공하고" |

주 사용자는 **운영자**다 ([§6.2](../mvp-plan-v1.md:187)).

## 이 제품은 의도적으로 얇다

> **관리자의 편의보다 실제 코트에서의 코치 사용성을 우선한다.**
> — [제품정의서 §18 원칙 9](../product-definition-v1.md:1166)

원칙이 명시적으로 후순위를 지정했다. 목업도 마지막에 그린다.

**그리고 파는 상품이 하나뿐이라 범위가 줄었다.**
[제품정의서 §6.2 학원 운영자용 웹](../product-definition-v1.md:182) 은 A~G 7블록에
[§6.3 커리큘럼 관리 시스템](../product-definition-v1.md) 까지 갖지만,
[MVP §6.7](../mvp-plan-v1.md:239) 은 화면 2개로 줄였다.

[MVP §2.2](../mvp-plan-v1.md) 가 제외를 명시한다 —
"**복잡한 다학원 SaaS, 수강권 조합, 정산 자동화**".
[§6.6](../mvp-plan-v1.md:228) 도 "외부 학원 대상 범용 SaaS와 다지점 운영" 을 뺀다.

## 핵심 Journey

관리자는 루프의 시작과 끝을 받친다. 학습자·코치처럼 순서대로 흐르지 않는다.

```
수업 전 (한 번)     ⑩ 패키지 관리      콘텐츠 · 일정 · 정원 · 가격을 세팅한다
운영 중 (반복)      ⑪ 예약/결제 관리    신청 → 결제 → 취소 → 출석 을 처리한다
```

**⑩ 이 학습자 ①②③④ 의 원본이다.** 여기서 만든 패키지·세션·일정·가격이
학습자 화면에 그대로 나간다.

**⑪ 이 코치 ⑧ 의 참가자 목록을 만든다.** 결제와 출석이 여기서 확정된다.

## ⑩ 패키지 관리

**핵심 행동: 콘텐츠·일정·정원·가격 설정** ([§6.7](../mvp-plan-v1.md:239))

§6.7 의 네 단어가 그대로 화면 구획이다.

| 구획 | 무엇 | 근거 |
|---|---|---|
| 콘텐츠 | 세션별 온라인 강의 등록 · 수업 전/후 자료 연결 | [MVP §6.3](../mvp-plan-v1.md:191) · [§5.3](../mvp-plan-v1.md) |
| 일정 | 패키지 및 세션 일정, 날짜·시간·장소·강사 | [MVP §6.4](../mvp-plan-v1.md:203) |
| 정원 | 잔여인원 — 세션당 최대 인원 | [MVP §6.4](../mvp-plan-v1.md:204) |
| 가격 | 패키지 전체 구매 또는 단일 결제방식 | [MVP §6.4](../mvp-plan-v1.md:205) |

**중점** — [MVP §5.3](../mvp-plan-v1.md) 이 세션당 제작물 6종(A 온라인 개념강의,
B 드릴 설명영상, C 시범·교정 클립, D 수업 전 자료, E 코치 운영자료, F 수업 후 자료)을
정의한다. 이 화면이 그것들을 세션에 붙이는 자리다.
[WS2 완료조건](../mvp-plan-v1.md)에 "파일명·썸네일·**메타데이터** 정리" 가 있다.

콘텐츠 쪽 산출물과 화면이 1:1로 맞는지 목업에서 확인한다 —
세션 6개 × 제작물 6종이면 붙일 슬롯이 36개다.

**미정** — 세션 수와 세션당 시간, 최대 인원, 가격이 전부 미확정이다.
[MVP §11 지금 바로 결정할 사항](../mvp-plan-v1.md:315)에 미체크로 남아 있다.

```
☐ 총 세션 수, 세션당 시간, 최대 인원
☐ 패키지 가격과 판매방식
```

목업은 [§4.3](../mvp-plan-v1.md) 권장값 4~6세션으로 그리고 자리만 잡는다.

## ⑪ 예약/결제 관리

**핵심 행동: 신청·결제·취소·출석 관리** ([§6.7](../mvp-plan-v1.md:239))

§6.7 의 네 단어가 **상태 전이**다. 목업에서 상태로 그린다.

```
신청  →  결제  →  (수업)  →  출석
          ↓                    ↓
        취소 · 환불          결석 · 노쇼
```

들어갈 것 — [MVP §6.4](../mvp-plan-v1.md:201) 의 학습자 쪽 대응물:

```
예약 변경 · 취소 요청 처리        학습자가 요청하고 관리자가 받는다
카드 결제 및 결제완료 확인
출석                            §6.2 코치 쪽에도 출석이 있다 → 누가 찍나 미정
```

**중점 둘**

1. **지표가 이 화면에서 나온다.** [MVP §10 운영](../mvp-plan-v1.md:308) —
   "**예약 오류율, 출석 처리시간**, 영상·피드백 등록시간".
   [§10 판매](../mvp-plan-v1.md:307) — "패키지 상세 → 결제 전환율, **환불·취소율**".
   목업에 이 숫자가 보이는 자리를 만들면 베타 운영이 쉬워진다.
2. **출석을 누가 찍는지 정해야 한다.** [MVP §6.2](../mvp-plan-v1.md:188) 는 코치 쪽에
   "출석" 을 적었고 [§6.7](../mvp-plan-v1.md:239) 은 관리자 쪽에 "출석 관리" 를 적었다.
   [제품정의서 §6.2 F. 출결 관리](../product-definition-v1.md)는 둘 다 둔다 —
   "코치 출결 · 수강생 출결 · QR 체크인 · **관리자 수동 처리**".

## MVP 밖 — 제품정의서엔 있으나 지금 아닌 것

[§6.2](../product-definition-v1.md:182) 7블록 중 MVP 에 들어오는 건 일부다.

| §6.2 블록 | MVP |
|---|---|
| A 학원 및 지점 관리 | 밖 — 다지점이 [§6.6](../mvp-plan-v1.md:228) 제외. 코트 등록만 최소 |
| B 강사 관리 | 부분 — ⑩ 의 "강사" 지정만. 등급·정산비율·평가는 밖 |
| C 스케줄 및 예약 관리 | **⑩⑪ 로 포함** — 단 반복일정·대기자·보강은 밖 |
| D 수강권 및 상품 관리 | 부분 — [§2.2](../mvp-plan-v1.md) 가 "수강권 조합" 제외 |
| E 회원 관리 | 부분 — 이탈 위험도·상담 메모·부상 이력은 밖 |
| F 출결 관리 | **⑪ 로 포함** — QR 체크인은 미정 |
| G 결제 및 정산 | 부분 — 결제는 필수, **정산 자동화는 제외** |
| §6.3 커리큘럼 관리 시스템 | 밖 — 드릴 라이브러리·세션 템플릿·평가표는 MVP 밖 |

[§13.2 MVP 1 학원용 웹](../product-definition-v1.md:947) 12항목과 비교하면
MVP 기획서(1개월)가 그보다 더 좁다. **제품정의서의 MVP 1 이 1개월 MVP 보다 크다.**

## 미결정

```
출석 주체        코치가 찍나 관리자가 찍나. §6.2 와 §6.7 이 다르게 적었다
결제수단        MVP §11 미체크. 최소 1개 필수라는 것만 정해져 있다
커리큘럼 입력    세션·드릴 데이터를 이 웹에서 넣나, 개발자가 직접 넣나
                MVP 는 패키지가 하나라 후자로도 성립한다
```
