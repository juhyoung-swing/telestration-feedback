# 관리자 — 웹

**MVP 플랫폼: 웹.** 데스크톱 폭으로 그린다. 셋 중 유일하게 모바일이 아니다.

|---|---|---|
| 지금 | [MVP 기획서 §6.2](../mvp-plan-v1.md:187) | **관리자 웹** |
| 장기 | [제품정의서 §6.1](../product-definition-v1.md:180) | "**웹을 기본 관리도구로** 제공하고" |

주 사용자는 **운영자**다 ([§6.2](../mvp-plan-v1.md:187)).

## 얇은 게 아니다 — §6.7 의 "콘텐츠" 한 단어가 제일 무겁다

[MVP §6.7](../mvp-plan-v1.md:239) 은 관리자를 화면 2개로 적었다.

```
패키지 관리      콘텐츠 · 일정 · 정원 · 가격 설정
예약/결제 관리   신청 · 결제 · 취소 · 출석 관리
```

`일정` · `정원` · `가격` 은 각각 필드 몇 개다. **`콘텐츠` 는 다르다.**
학습자·코치 화면에 뜨는 필드를 역산하면 전부 여기서 입력돼야 한다.

**필드 25개가 "콘텐츠" 한 단어 안에 있었다.** 그 뒤의 원본 스키마는 더 크다.

```
§6.3 C 세션 템플릿      20필드
§6.3 D 드릴            21필드 · 드릴마다
§5.3   세션당 미디어      6종 (A 개념강의 ~ F 수업 후 자료)
```

세션 4~6개([§4.3](../mvp-plan-v1.md:84) 권장)면 입력란이 이렇게 된다.

```
세션 4개  4×(20+6) + 드릴 8개×21   =  272
세션 6개  6×(20+6) + 드릴 12개×21  =  408
```

**MVP 전체에서 입력란이 가장 많은 화면이다.** 앞서 이 문서는 §6.3 커리큘럼 관리
시스템을 "MVP 밖"으로 적었는데 그건 틀렸다 — 라이브러리 구조는 밖이지만
**세션 단위 콘텐츠 입력은 필수**다. 없으면 L3 · L6 · L7 · C1 이 빈 화면이다.

## 그래서 화면을 넷으로 나눴다

| ID | 화면 | 핵심 행동 | 근거 |
|---|---|---|---|
| A0 | 로그인 · 강사 초대 | 들어오고 코치를 초대한다 | §6.2 A · B |
| A1 | 패키지 · 일정 · 가격 | 상품과 회차를 세팅한다 | §6.7 |
| **A2** | **세션 편집기** | **세션 내용과 미디어를 넣는다** | §6.7 "콘텐츠" · §6.3 C · D · §5.3 |
| A3 | 예약 / 결제 관리 | 신청 · 결제 · 취소 · 출석 | §6.7 |

§6.7 의 "패키지 관리" 한 행을 A1 과 A2 로 쪼갰다. 성격이 다르다 —
**A1 은 회차마다 바뀌고 A2 는 한 번 쓰면 굳는다.**

## 핵심 Journey

```
준비 (한 번)      A0 강사 초대 → A2 세션 편집기 → A1 패키지·일정·가격
운영 중 (반복)    A3 예약/결제 관리      신청 → 결제 → 취소 → 출석
```

**A2 가 학습자 L3 · L6 · L7 과 코치 C1 의 원본이다.**
**A1 이 학습자 L1 · L4 의 원본이다.**
**A3 이 코치 C1 의 참가자 목록을 확정한다.**

## A2 세션 편집기 — MVP 에서 가장 큰 화면

세션 하나가 아래를 갖는다. [§6.3 C](../product-definition-v1.md:327) 20필드 중
소비 화면이 실제로 쓰는 것만 남겼다.

```
정체성      세션명 · 한 문장 목표 · 대상 레벨 · 필요 기술
                                        → L3 학습 목표 · L6 관련 기술
운영        총 소요시간 · 단계별 시간 · 권장 인원 · 준비물
                                        → L6 예상 진행순서 · 참가자 수 · 준비물
교육 내용    성공 기준 · 흔한 오류 · 코칭 키워드 · 안전 유의사항
                                        → L3 자주 하는 실수 · C1 코칭 포인트 · 주의사항
연결        수업 전 시청자료 · 수업 후 복습자료 · 과제 · 다음 추천
                                        → L6 사전 영상 · L7 복습 강의 · 과제
학습자 입력   자가진단 질문                → L3 셀프 체크리스트 · L6 자가진단
```

### 세션당 미디어 6종

[MVP §5.3](../mvp-plan-v1.md:135) 이 제작물을 정의했다. 이 화면이 그걸 세션에 붙인다.

| 제작물 | 길이 | 붙는 곳 |
|---|---|---|
| A 온라인 개념강의 | 5~12분 | L3 영상 |
| B 드릴 설명영상 | 1~3분/드릴 | L3 코트 그래픽 · C1 드릴 |
| C 시범 · 교정 클립 | 30초~2분 | L3 자주 하는 실수 |
| D 수업 전 자료 | 모바일 1~2화면 | L6 |
| E 코치 운영자료 | 1~3페이지 | C1 타임박스 · 관찰항목 |
| F 수업 후 자료 | 모바일 1~2화면 | L7 |

[§5.4 제작 프로세스](../mvp-plan-v1.md:144) 8·9단계가 이 화면의 일이다 —
"앱 등록용 메타데이터와 썸네일 제작", "최종본 업로드 및 수업과 연결".

### 드릴

**드릴 데이터는 필요하고 드릴 라이브러리는 불필요하다.**
[§6.4 수업 시작 전](../product-definition-v1.md:391)이 코치 화면에 "드릴 배치도"를
요구하므로 배치도를 가진 드릴이 존재해야 한다. 다만 [§6.3 D](../product-definition-v1.md:352)
21필드 중 종목 · 기술 분류 · 대상 레벨 · 관련 평가항목은 **재사용을 위한 것**이라
패키지가 하나인 MVP 에서는 뺀다.

```
남기는 것   드릴명 · 목적 · 코트 배치도 · 선수 위치 · 코치 위치 · 진행경로
           준비물 · 진행시간 · 인원수 · 성공 기준 · 자주 발생하는 실수
           코치 교정문구 · 시범 영상
빼는 것     종목 · 기술 및 전술 분류 · 대상 레벨 · 관련 세션 · 관련 평가항목
           난이도 조절방법 · 숏폼 설명 영상
```

**배치도를 어떻게 넣나** — 좌표 편집기를 만들 것인가, 이미지 업로드로 받을 것인가.
[§5.3 B](../mvp-plan-v1.md:138) 가 드릴 설명영상에 "코트 배치, 피딩, 이동경로"를 두므로
**영상·이미지로 대체 가능하다.** 편집기는 MVP 밖으로 두는 게 맞다고 본다.

## A3 예약 / 결제 관리

§6.7 의 네 단어가 **상태 전이**다. 목업에서 상태로 그린다.

```
신청  →  결제  →  (수업)  →  출석
          ↓                    ↓
        취소 · 환불          결석 · 노쇼
```

```
예약 변경 · 취소 요청 처리      학습자가 요청하고 관리자가 받는다
카드 결제 및 결제완료 확인
출석                        코치가 현장에서 찍고 관리자가 예외를 수동 처리 (§6.2 F)
```

**중점** — 지표가 이 화면에서 나온다.
[§10 운영](../mvp-plan-v1.md:308) "예약 오류율, 출석 처리시간",
[§10 판매](../mvp-plan-v1.md:307) "패키지 상세 → 결제 전환율, 환불·취소율".
목업에 이 숫자가 보이는 자리를 만들면 베타 운영이 쉬워진다.

## 아직 안 정해진 것

### A2 를 만드나, 콘텐츠를 시드로 넣나 ← 금요일 결정

**앞서 이 문서는 "§6.7 콘텐츠 설정이 답"이라며 이걸 결정된 것으로 적었다. 틀렸다.**
어느 문서도 콘텐츠를 **누가 어디로** 넣는지 정하지 않았다.
[§5.4](../mvp-plan-v1.md:154) 는 "최종본 업로드 및 수업과 연결"이라고만 하고,
[§7](../mvp-plan-v1.md:258) Week 2 통합검증은 "첫 콘텐츠 앱 등록"이라고만 한다.

| | A2 를 만든다 | 콘텐츠를 시드로 넣는다 |
|---|---|---|
| 입력란 | 272 ~ 408개를 UI 로 | 개발자가 JSON · DB 로 |
| 만드는 비용 | MVP 최대 화면 하나 추가 | 0 — 화면이 없다 |
| 고치는 비용 | 운영자가 바로 고친다 | 매번 개발자를 거친다 |
| §6.7 과 | 화면이 2개가 아니라 4개가 된다 | **§6.7 의 2개와 맞는다** |
| 성립 조건 | — | 패키지가 하나일 때만 |

**중간안** — 텍스트 필드는 시드로 넣고 **미디어 업로드와 일정·가격만 UI 에 둔다.**
[§5.4](../mvp-plan-v1.md:144) 의 촬영이 Week 2~4 에 걸쳐 있어 미디어는 계속 바뀌지만,
텍스트는 Week 3 에 "전체 커리큘럼 최종"으로 굳는다([§7](../mvp-plan-v1.md:259)).
**굳는 것은 시드로, 계속 바뀌는 것은 UI 로** 두는 갈래다.
