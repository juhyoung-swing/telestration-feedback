# 지금 만들 화면

**1개월 MVP 의 목업 대상.** 근거는 [MVP 기획서 §6.7 핵심 화면](../mvp-plan-v1.md:239) 이고,
각 화면에 들어갈 항목은 [제품정의서](../product-definition-v1.md) 에서 가져온다.

```
screens/
  player-app.md    학습자 — 화면 5개 + 목록 2개
  coach-app.md     코치 — 화면 2개
  admin-web.md     관리자 — 화면 5개
```

## 제품 셋과 플랫폼

**두 문서가 플랫폼을 다르게 적었다.** MVP 기획서가 최신이고 운영 문서라 그쪽을 따른다.

| 제품 | 주 사용자 | 제품정의서 (장기) | **MVP 기획서 §6.2 (지금)** |
|---|---|---|---|
| 관리자 | 운영자 | 웹 — [§6.1](../product-definition-v1.md:180) "웹을 기본 관리도구로" | **관리자 웹** |
| 코치 | 김기준 대표 · Sub Coach | 모바일 앱 — [§6.1](../product-definition-v1.md:180) | **코치 모바일 웹/PWA** |
| 학습자 | 커리큘럼 구매자 | 모바일 앱 — [§3](../product-definition-v1.md:63) | **학습자 앱/모바일 웹** |

```
지금 (MVP)   전부 웹.  관리자는 데스크톱 폭, 코치·학습자는 모바일 폭
장기         코치·학습자는 네이티브 앱으로 간다
```

**목업은 셋 다 웹으로 그린다.** 코치·학습자는 모바일 뷰포트로 그리고 네이티브 앱
크롬(탭바·상태바)을 그리지 않는다. → [아직 안 정해진 것](#아직-안-정해진-것) 참고

## 핵심 Journey — 화면 하나짜리가 아니라 한 바퀴다

[MVP 기획서 §2.3](../mvp-plan-v1.md) 의 6단계가 이 루프다. 화면 번호를 붙이면 이렇게 된다.

```
학습자                          코치                        관리자
──────────────────────────────────────────────────────────────────
① 커리큘럼 상세      구매
③ 세션 강의 상세   예습                                    ⑩ 커리큘럼 관리
④ 예약·결제       결제  ─────────────────────────────→   ⑪ 예약/결제 관리
⑥ 수업 전 상세     목표·자가진단 입력 ──→  ⑧ 오늘의 수업
                                          수업 진행·촬영
                                       ⑨ 수업 결과 입력
⑦ 수업 후 상세  ←──────────────────────  영상·클립·피드백
③ 세션 강의 상세   복습  ←── 복습 강의 연결
```

**두 지점에서 제품이 맞물린다. 목업에서 짝을 맞춰야 한다.**

```
⑥ → ⑧   학습자가 수업 전에 넣은 자가진단 질문 · 코치에게 전달할 요청 을
         코치의 "오늘의 수업" 이 받는다        제품정의서 §7.5 · §6.4
⑨ → ⑦   코치가 고른 좋은 장면·교정 장면과 피드백이
         학습자의 "수업 후 상세" 에 그대로 뜬다   MVP §6.5
```

[제품정의서 §12 Scenario 1·2](../product-definition-v1.md:898) 가 같은 왕복을
온라인→오프라인 / 오프라인→온라인 으로 서술한다.

## 전 제품에 걸리는 제약 넷

목업을 그릴 때 화면마다 확인한다. 근거는 [§18 첫 번째 제품 원칙](../product-definition-v1.md:1156) 과
[온보딩 §9](../../team/onboarding-guide-v1.md:129) 다.

### 1. 코치 피드백은 5분 안에 끝나야 한다

> 코치는 추가 업무 부담 없이 **5분 안팎으로** 좋은 피드백을 남길 수 있는가?
> — [온보딩 §9](../../team/onboarding-guide-v1.md:129)

[MVP §10](../mvp-plan-v1.md:308) 도 운영 지표로 "영상·피드백 등록시간"을 잡았다.
**숫자가 붙은 유일한 설계 제약이다.** 화면 ⑨ 가 이걸로 평가받는다.

### 2. AI 는 초안까지, 판단은 코치가

> 코치는 자동 생성된 초안을 검토하고 수정한 후 발송한다.
> **AI가 최종 코칭 판단을 내리지는 않는다.** — [§6.5](../product-definition-v1.md:461)
>
> AI가 코치의 최종 판단을 대신하지 않는다. — [§18 원칙 4](../product-definition-v1.md:1161)

목업에서 빈 텍스트박스를 그리면 안 된다. **초안이 채워진 상태**가 기본 화면이다.

### 3. 피드백에는 항상 장면이 붙는다

> 모든 피드백은 실제 장면이나 평가항목에 근거해야 한다. — [§18 원칙 3](../product-definition-v1.md:1160)

⑨ 와 ⑦ 양쪽에서 코멘트는 항상 클립·타임스탬프를 물고 있어야 한다.

### 4. 기능 수보다 루프의 완결성

> 관리자의 편의보다 실제 코트에서의 코치 사용성을 우선한다. — [§18 원칙 9](../product-definition-v1.md:1166)
> 기능 수보다 학습 순환의 완결성을 우선한다. — [§18 원칙 10](../product-definition-v1.md:1167)

원칙 9 는 **사용성**의 우선순위다. 만드는 순서는 [§7](../mvp-plan-v1.md:255)이 정하고,
거기서도 운영화면이 Week 4 로 가장 뒤다.

## 순서 — 문서가 정해뒀다

**목업은 고르는 게 아니라 11개를 다 그리는 것이다.**
[MVP §7 1개월 통합 일정](../mvp-plan-v1.md:255)이 WS3(제품)을 주차로 끊었고,
**설계(=목업)는 Week 1 한 칸**이다.

| 주차 | WS3 제품 | 해당 화면 |
|---|---|---|
| Week 1 | 화면 · 데이터 · 결제 **설계** | 전부 |
| Week 2 | 강의 · 커리큘럼 · 예약 · 결제 구현 | L0 L1 L2 L3 L4 L5 |
| Week 3 | 수업 전후 · 영상 · 피드백 구현 | L6 L7 · C0 C1 C2 |
| Week 4 | 통합 QA · 알림 · **운영화면** | A0 A1 A2 A3 A4 |

구현 순서는 **학습자 구매·예약 → 수업 전후·영상·피드백 → 관리자**다.
관리자가 마지막인 것은 [§18 원칙 9](../product-definition-v1.md:1166)와도 맞는다.

> 주차 자체는 다시 끊어야 한다. MVP 기획서는 2026-07-22 기준 4주인데 오늘이 08-19 이고
> 사업 로드맵은 Phase 1 을 10월로 잡았다. → [docs/README.md](../../README.md) 참고

☐ 총 세션 수, 세션당 시간, 최대 인원      ② 목록과 ⑩ 커리큘럼 관리의 행 수
☐ 커리큘럼 가격과 판매방식                 ① 커리큘럼 상세와 ④ 예약·결제

아래 둘은 §11 에 없고 **두 문서가 서로 다르게 적어서** 생긴 것이다.

### My Journey 를 MVP 에 넣나

`My Journey` 는 제품정의서에 4번 나오고 그중 하나는 제품 원칙이다.

| 위치 | 내용 |
|---|---|
| [§7.1](../product-definition-v1.md:471) | "앱의 중심은 예약 화면이 아니라 **My Journey**다" |
| [§11](../product-definition-v1.md:861) | "**학습자 앱의 핵심 화면이다**" |
| [§13.2](../product-definition-v1.md:983) | **MVP 1** 학습자용 앱 기능 목록에 포함 |
| [§18 원칙 5](../product-definition-v1.md:1162) | "학습자의 영상과 평가 이력은 하나의 Journey에 축적된다" |

**그런데 MVP 기획서에는 `Journey` 라는 단어가 0건이다.** §6.7 에도 없다.
[player-app.md](player-app.md#my-journey-범위-미정) 에 MVP 에서 채울 수 있는 항목만 골라 뒀다.

### 학습자 쪽이 웹인가 앱인가

MVP §6.2 가 "학습자 **앱/모바일 웹**" 이라고 둘 다 적었다. 목업은 모바일 웹으로
그리면 되지만, 제품정의서가 앱을 전제한 기능이 둘 있다.

| 기능 | 제품정의서 | MVP 기획서 |
|---|---|---|
| 촬영 | [§8.2 방식 3](../product-definition-v1.md:638) "**앱에서 직접 촬영**" | [§6.5](../mvp-plan-v1.md:216) "촬영·**업로드**" — 완화됨 |
