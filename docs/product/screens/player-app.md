# 학습자 — 앱/모바일 웹

**MVP 플랫폼: 모바일 웹.** 목업은 모바일 뷰포트로 그리고 네이티브 앱 크롬을 그리지 않는다.

| | 문서 | 표기 |
|---|---|---|
| 지금 | [MVP 기획서 §6.2](../mvp-plan-v1.md:189) | 학습자 **앱/모바일 웹** — 둘 다 적혀 있다 |
| 장기 | [제품정의서 §3](../product-definition-v1.md:63) | Product B. Player App — **모바일 앱** |

주 사용자는 **패키지 구매자**다 ([§6.2](../mvp-plan-v1.md:189)).

## 이 제품의 성격 — 예약 앱이 아니다

> 학습자가 수업을 찾고 예약하는 앱인 동시에, 자신의 스포츠 학습과 경기 데이터를
> 축적하는 개인 성장 플랫폼이다. **앱의 중심은 예약 화면이 아니라 My Journey다.**
> — [제품정의서 §7.1](../product-definition-v1.md:467)

MVP 에서 이 성격이 드러나는 곳은 **⑦ 수업 후 상세**다. 여기가 비면 앱이 예약 앱이 된다.

## 핵심 Journey

[MVP §2.3](../mvp-plan-v1.md) 의 6단계 중 학습자 몫이다.

```
① 패키지 상세      "이 과정이 내 문제를 푸나"        → 구매
② 세션 강의 목록    "몇 번째 세션인가"
③ 세션 강의 상세    예습                            → 수업 예약   ← 전환점
④ 예약·결제        일정 선택                        → 결제 완료
⑤ 내 예약 목록      확인 · 변경 · 취소
⑥ 수업 전 상세      목표 확인 + 자가진단 입력         → 코치에게 전달
   ─── 오프라인 수업 ───
⑦ 수업 후 상세      내 영상 · 코치 피드백 · 숙제      → 복습으로 ③ 으로 되돌아감
```

**③ 이 사업모델의 핵심 기제다.**

> 온라인 강의는 단순 콘텐츠 판매가 아니라 **오프라인 수업의 수요를 발생시키는 역할**을 한다.
> — [§7.3](../product-definition-v1.md:533)

**⑦ 이 루프를 닫는다.** 여기서 ③ 으로 되돌아가지 않으면 한 바퀴가 아니라 직선이다.

## ① 패키지 상세

**핵심 행동: 과정 이해 → 구매** ([§6.7](../mvp-plan-v1.md:239))

매출 경로의 시작이다. [MVP §10](../mvp-plan-v1.md:307) 이 판매 지표를
"**패키지 상세 → 결제 전환율**" 로 잡았다.

들어갈 것 — [MVP §6.3](../mvp-plan-v1.md:191):

```
Game Lesson Package 소개
커리큘럼 구성                세션 몇 개, 각 세션이 무엇인지
```

[MVP §2.1](../mvp-plan-v1.md) 의 대상과 [§2.1 제품 가설](../mvp-plan-v1.md) 이 이 화면의 문구다 —
"실제 경기력 향상을 원하는 성인 테니스 동호인".

**중점** — [MVP §10 고객 지표](../mvp-plan-v1.md:310)가 "다음 패키지 또는 추가수업 구매의향,
추천의향" 이고 [온보딩 §9](../../team/onboarding-guide-v1.md:130) 가
"기존 일반 레슨보다 **체계적이고 결과가 남는다**는 인상을 주는가" 를 묻는다.
이 화면이 그 인상을 만든다.

## ② 세션 강의 목록

**§6.7 에 없는 화면.** [MVP §6.3](../mvp-plan-v1.md:191) 의 "세션별 온라인 강의 목록" 에서 나온다.

세션 수는 미정 — [MVP §4.3](../mvp-plan-v1.md) 이 4~6개를 권장하고 확정은 워크숍이다.
[§4.3 의 테마 예시](../mvp-plan-v1.md)를 목업 더미 데이터로 쓸 수 있다.

```
Session 1  게임 진단과 확률 높은 플레이
Session 2  공간 만들기와 방향 선택
Session 3  공격 전환과 마무리
Session 4  수비와 중립화
Session 5  서브·리턴부터 시작하는 패턴
Session 6  통합 매치플레이와 개인 처방
```

수강완료 표시가 필요하다 ([§6.3](../mvp-plan-v1.md:191)).

## ③ 세션 강의 상세 ★ 전환점

**핵심 행동: 예습·복습 → 수업 예약** ([§6.7](../mvp-plan-v1.md:239))

들어갈 것 — [제품정의서 §7.3 콘텐츠 상세 화면](../product-definition-v1.md:504):

```
제목 · 대상 레벨 · 학습 목표
영상
핵심 포인트
코트 그래픽
자주 하는 실수
셀프 체크리스트
관련 드릴
관련 오프라인 수업 · 관련 코치
수업 예약 버튼          ← 이것
영상 리뷰 신청 버튼      → MVP 밖 (원격 리뷰 상품은 §8.4)
저장 · 수강완료 처리
```

MVP 축약판은 [§6.3](../mvp-plan-v1.md:191) — 영상, 목표, 핵심 포인트, 코트 그래픽, 흔한 실수,
수강완료 표시, 관련 오프라인 세션 보기, **강의에서 바로 수업 예약·결제로 이동**.

**중점 — 예약 버튼이 강의 밖으로 나가는 6단계의 입구다.** [§7.3](../product-definition-v1.md:524):

```
1 이 강의를 가르치는 코치   2 가까운 아카데미   3 가능한 날짜
4 개인 또는 그룹 수업       5 보유 수강권 또는 신규 구매   6 예약 확정
```

MVP 는 학원·코치가 하나뿐이라 1·2 가 접힌다. **3~6 만 남는다.**

수업 후에는 같은 화면이 복습으로 다시 쓰인다 —
[§6.3](../mvp-plan-v1.md:191) "수업 후 관련 복습강의로 다시 연결".

## ④ 예약·결제

**핵심 행동: 일정 선택 → 결제 완료** ([§6.7](../mvp-plan-v1.md:239))

들어갈 것 — [MVP §6.4](../mvp-plan-v1.md:201):

```
패키지 및 세션 일정 조회
날짜 · 시간 · 장소 · 강사 · 잔여인원
패키지 전체 구매 또는 단일 결제방식
카드 결제 및 결제완료 확인
```

> **중요한 범위 수정** … 이번 MVP의 목적은 실제 Game Lesson Package 판매까지
> 검증하는 것이므로 **최소 1개의 결제수단은 필수 범위**로 포함한다.
> — [MVP §6.4](../mvp-plan-v1.md:211)

**MVP 에서 접히는 것** — [제품정의서 §7.4 탐색 기준](../product-definition-v1.md:537) 12종
(학원별·지역별·코치별·레벨별·가격별 …) 은 상품이 하나라 대부분 불필요하다.
[§7.4 예약 과정](../product-definition-v1.md:552) 9단계 중 "수강권 선택" 도 MVP 에서는
수강권 조합이 없어 접힌다 ([§2.2](../mvp-plan-v1.md) 가 "수강권 조합" 을 제외).

**미결정: 어느 PG.** [MVP §11](../mvp-plan-v1.md:313) 에 미체크로 남아 있다.

## ⑥ 수업 전 상세

**핵심 행동: 목표·드릴·사전영상 확인** ([§6.7](../mvp-plan-v1.md:239))

들어갈 것 — [제품정의서 §7.5 수업 전](../product-definition-v1.md:580):

```
수업 주제 · 목표
예상 진행순서
관련 기술
담당 코치 · 참가자 수
준비물
사전 영상
자가진단 질문             ← 학습자가 입력한다
코치에게 전달할 요청        ← 학습자가 입력한다
```

콘텐츠 쪽 대응물은 [MVP §5.5 수업 전 자료 템플릿](../mvp-plan-v1.md) 이다 —
테마와 한 문장 목표, 실제 게임에서 발생하는 장면, 핵심 판단기준 2~4개,
수업 단계와 시간 배분, 사전 온라인 강의, 스스로 확인할 질문, 준비물.

**중점 — 아래 두 칸이 코치 화면으로 넘어간다.** 목업에서 ⑧ 과 짝을 맞춰야 한다.

```
자가진단 질문 · 코치에게 전달할 요청  →  코치 ⑧ 오늘의 수업
```

[MVP §10 콘텐츠 지표](../mvp-plan-v1.md:306)가 "**수업 전 온라인 강의 시청률**" 이고
[§7.4 알림](../product-definition-v1.md:569)에 "**사전 강의 미시청**" 알림이 있다.
이 화면이 미시청을 잡아내는 자리다.

## ⑦ 수업 후 상세 ★ 루프가 닫히는 곳

**핵심 행동: 영상·코치 피드백·숙제 확인** ([§6.7](../mvp-plan-v1.md:239))

들어갈 것 — [제품정의서 §7.5 수업 후](../product-definition-v1.md:593):

```
실제 진행한 커리큘럼
출석정보
전체 영상
자동 편집된 영상
주요 하이라이트
코치 음성 또는 텍스트 피드백
평가 결과
수업 중 잘한 점 · 개선할 점
과제
복습 강의          ← ③ 으로 되돌아가는 링크
다음 추천 수업
코치 평가
```

MVP 범위는 [§6.5](../mvp-plan-v1.md:223) 가 좁힌다 —
"학습자 앱에서 **전체 영상 또는 지정 클립** 확인". 자동 편집·하이라이트 자동 생성은
[§6.6](../mvp-plan-v1.md:233)이 제외한 자동 처리에 걸린다.

**중점 셋**

1. **코치 ⑨ 의 출력이 그대로 여기 뜬다.** 좋은 장면 / 교정 장면 분류, 장면별 코멘트,
   학생별 잘한 점·개선점·숙제 ([§6.5](../mvp-plan-v1.md:214)). 목업에서 같은 구조로 그린다.
2. **[§18 원칙 3](../product-definition-v1.md:1160)** — 코멘트는 항상 클립·타임스탬프를 물고 있어야 한다.
3. **열람률이 지표다.** [MVP §10 학습](../mvp-plan-v1.md:309) — "수업 후 영상 열람률,
   피드백 열람률, 숙제 수행률". [온보딩 §9](../../team/onboarding-guide-v1.md:128) —
   "수업 후 영상과 코치 피드백을 고객이 **다시 보는가**".
