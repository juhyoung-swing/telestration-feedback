**MVP 플랫폼: 모바일 웹/PWA.** 문서에 PWA 로 명시돼 있다.

| | 문서 | 표기 |
|---|---|---|
| 지금 | [MVP 기획서 §6.2](../mvp-plan-v1.md:188) | 코치 **모바일 웹/PWA** |
| 장기 | [제품정의서 §6.1](../product-definition-v1.md:180) | "코치의 현장 사용을 위한 **모바일 앱**을 별도로 제공한다" |

주 사용자가 **김기준 대표 및 Sub Coach** 로 문서에 실명으로 적혀 있다
([§6.2](../mvp-plan-v1.md:188)). 첫 사용자가 미팅 상대 본인이다.

## 이 제품이 우선순위 1위다 — 원칙에 적혀 있다

> **관리자의 편의보다 실제 코트에서의 코치 사용성을 우선한다.**
> — [제품정의서 §18 원칙 9](../product-definition-v1.md:1166)

그리고 **숫자가 붙은 유일한 설계 제약**을 가진 제품이다.

> 코치는 추가 업무 부담 없이 **5분 안팎으로** 좋은 피드백을 남길 수 있는가?
> — [온보딩 §9](../../team/onboarding-guide-v1.md:129)

[MVP §10 운영 지표](../mvp-plan-v1.md:308)의 "영상·피드백 등록시간" 과
[§10 코치 지표](../mvp-plan-v1.md:311)의 "**피드백 업무가 감당 가능한지**" 가 같은 것을 본다.

## 핵심 Journey

[제품정의서 §6.4](../product-definition-v1.md:378) 가 코치의 하루를 3단계로 나눈다.
MVP 화면은 2개인데 **⑧ 이 "수업 시작 전", ⑨ 가 "수업 종료 후" 를 맡고
"수업 중" 은 화면이 없다.**

```
수업 시작 전   ⑧ 오늘의 수업        참가자 · 커리큘럼 · 지난 피드백 · 학습자 요청
수업 중        (화면 없음)          MVP 에서 §6.4 "수업 중" 10항목은 범위 밖
수업 종료 후   ⑨ 수업 결과 입력      영상 · 클립 · 피드백        ← 5분 제약
```

**⑨ 의 출력이 학습자 ⑦ 로 그대로 간다.** 목업에서 같은 구조로 그린다.

---

## ⑧ 오늘의 수업

**핵심 행동: 참가자와 커리큘럼 확인** ([§6.7](../mvp-plan-v1.md:239))

들어갈 것 — [제품정의서 §6.4 수업 시작 전](../product-definition-v1.md:380).
"코치는 모바일 앱에서 다음을 확인한다":

```
오늘의 수업
참가 학생
학생별 레벨
이전 수업내용
이전 코치 피드백
학생의 최근 영상
오늘의 커리큘럼
드릴 배치도
코칭 포인트
주의사항
```

MVP 범위는 [§6.2](../mvp-plan-v1.md:188) 가 좁힌다 — "오늘 수업 확인, **출석**,
영상 업로드, 학생별 피드백". 출석이 여기 붙는다.

**중점 둘**

1. **학습자 ⑥ 이 넣은 두 칸을 받는다.**
   [§7.5 수업 전](../product-definition-v1.md:590) 의 `자가진단 질문` ·
   `코치에게 전달할 요청` 이 이 화면에 떠야 학습자가 쓴 게 의미를 갖는다.
2. **커리큘럼이 화면에 있어야 한다.**
   [§18 원칙 2](../product-definition-v1.md:1159) "모든 수업은 커리큘럼 또는 드릴과
   연결되어야 한다" · [원칙 1](../product-definition-v1.md:1158) "모든 수업에는 명확한
   학습목표가 있어야 한다". 콘텐츠 쪽 대응물이
   [MVP §5.3 E. 코치 운영자료](../mvp-plan-v1.md) — 타임박스, 드릴 순서,
   코칭 언어, 관찰항목.

[MVP §10 코치 지표](../mvp-plan-v1.md:311)가 "커리큘럼이 **실제 수업을 더 쉽게 만들었는지**"
를 묻는다. 이 화면이 그 답이다.

## ⑨ 수업 결과 입력 ★ 목업 1순위

**핵심 행동: 영상·클립·피드백 등록** ([§6.7](../mvp-plan-v1.md:239))

### MVP 범위 — 여기가 정확한 경계다

[MVP §6.5 기능 범위 C](../mvp-plan-v1.md:214):

```
코치 또는 운영자가 수업 영상을 촬영·업로드
영상이 해당 수업 및 참가 학생과 연결
코치가 핵심 장면의 시작·종료 구간 선택
좋은 장면 · 교정 장면 분류              ← 2분류. 그 이상 아님
장면별 텍스트 또는 음성 코멘트
학생별 잘한 점 · 개선점 · 숙제 작성
관련 온라인 강의와 다음 수업 연결
학습자 앱에서 전체 영상 또는 지정 클립 확인
```

### 피드백은 3블록 고정이다

[제품정의서 §6.5 빠른 피드백 방식](../product-definition-v1.md:437):

> **긴 글을 매번 작성하지 않아도 되도록 구조화한다.**

문서의 예시가 그대로 목업의 골격이다.

```
오늘 잘한 점     준비가 빨라짐 · 타점이 앞에서 형성됨 · 크로스코트 방향성이 안정적임
개선할 점        스플릿스텝 타이밍 · 높은 공에서 간격 확보 · 샷 이후 리커버리
다음 과제        포핸드 크로스코트 20회 연속 · 스플릿스텝 영상 촬영 · 관련 온라인 강의 시청
```

"다음 과제" 의 세 번째 항목이 **학습자를 ③ 세션 강의 상세로 되돌려보낸다.**

### AI 는 초안까지만

> 코치는 **자동 생성된 초안을 검토하고 수정한 후 발송한다.**
> AI가 최종 코칭 판단을 내리지는 않는다. — [§6.5](../product-definition-v1.md:461)
>
> AI가 코치의 최종 판단을 대신하지 않는다. — [§18 원칙 4](../product-definition-v1.md:1161)

**목업에서 빈 텍스트박스를 그리면 안 된다.** 초안이 채워진 상태가 기본 화면이고,
코치의 동작은 "쓰기" 가 아니라 "고치고 보내기" 다. 5분 제약이 여기서 지켜진다.

[§6.4 수업 종료 후](../product-definition-v1.md:408)에 "수업 내용 **자동 요약 초안**" ·
"하이라이트 **자동 생성**" 이 있다. 자동 생성 쪽은 MVP 밖이므로
**초안의 출처를 목업에서 정해야 한다** → [미결정](#미결정)

### 영상 기능의 목적이 뒤집혀 정의돼 있다

> 영상 기능의 목적은 **AI 코치를 만드는 것이 아니다.**
> 목적은 다음과 같다.
> - **코치가 짧은 시간에 영상을 검토하도록 지원**
> - 수업을 자동으로 정리
> - 학습자가 자신의 변화를 시각적으로 확인
> - 좋은 장면과 문제 장면을 쉽게 공유
> - 실제 영상에 근거한 사람 중심의 코칭 제공
> — [§8.1](../product-definition-v1.md:611)

첫 항목이 이 화면의 설계 목표다.

### MVP 밖 — 리뷰 도구

[§8.4 코치 리뷰](../product-definition-v1.md:678) 11종 중 MVP 는 앞의 둘 정도다.

| 도구 | MVP |
|---|---|
| 특정 시점 댓글 | **포함** — §6.5 "장면별 텍스트 또는 음성 코멘트" |
| 음성 설명 | **포함** — 같은 줄 |
| 화면 정지 · 슬로모션 | 밖 |
| 선과 화살표 그리기 | 밖 |
| 이전 영상과 나란히 비교 · 모범 영상과 비교 | 밖 |
| 짧은 영상 답변 | 밖 |
| 평가항목 태그 | 밖 — 평가체계가 [§9](../product-definition-v1.md) · MVP 2 |
| 관련 강의 첨부 · 다음 드릴 첨부 | **포함** — §6.5 "관련 온라인 강의와 다음 수업 연결" |

## MVP 밖 — 제품정의서엔 있으나 지금 아닌 것

[§6.5 코치용 앱 주요 화면](../product-definition-v1.md:424) 10개 중 MVP 는 2개뿐이다.

| §6.5 화면 | MVP |
|---|---|
| 1 오늘의 일정 | **⑧ 로 포함** |
| 2 수업 상세 | **⑧ 로 포함** |
| 3 학생 프로필 | 부분 — ⑧ 의 "학생별 레벨 · 이전 피드백" 으로 축약 |
| 4 촬영 · 5 영상 하이라이트 · 6 피드백 작성 | **⑨ 로 포함** |
| 7 드릴 라이브러리 | 밖 — 커리큘럼 관리가 관리자 웹 §6.3 |
| 8 강사 교육 | 밖 |
| 9 메시지 | 밖 — [§6.6](../mvp-plan-v1.md:229) 이 채팅 제외 |
| 10 정산 | 밖 — [§2.2](../mvp-plan-v1.md) 가 "정산 자동화" 제외 |

[§6.4 수업 중](../product-definition-v1.md:395) 10항목(드릴별 타이머 · 빠른 메모 ·
학생별 태그 · 좋은 장면 표시 …)도 MVP 화면이 없다. **현장에서 실시간으로 쓰는 화면이
MVP 에 없다**는 뜻이라 금요일에 코치 의견을 들을 지점이다.

## 미결정

```
피드백 초안의 출처
  §6.4 는 "자동 요약 초안" 을 전제하고 §6.5 는 "자동 생성된 초안" 을 검토한다고 한다.
  그런데 §6.6 은 "AI가 직접 작성하는 코칭 피드백" 을 제외한다.
  → 초안을 무엇이 만드는가. 전사 기반인가, 템플릿인가, 지난 회차 복사인가.

촬영 주체
  §8.2 방식 1(학원 고정 카메라) · 방식 2(코치 스마트폰 삼각대) 중 MVP 는 무엇인가.
  방식 2 는 "코치 앱에서 수업 선택 후 촬영" 이라 앱 내 촬영을 전제한다.
  MVP §6.5 는 "촬영·업로드" 로 완화돼 있어 모바일 웹으로도 성립한다.

수업 중 화면
  §6.4 "수업 중" 10항목이 MVP 화면에 없다. 코치가 코트에서 폰을 볼 여유가 있는가를
  본인에게 확인해야 한다.
```
