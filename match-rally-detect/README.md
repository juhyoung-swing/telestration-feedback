# 랠리 검출

경기 영상에서 랠리가 언제 시작하고 끝나는지 표시한다.
정렬·필터·특정 포인트로 점프가 여기서 나온다.

**새로 만든다.** 기존 구현은 `../_archive/exp1-match/rally_scan_px.py` 에 있고,
왜 버리는지는 아래에 적었다.

## 기존 구현을 왜 버리나

원리가 "두 선수가 동시에 멈춘 순간 = 서브 직전" 이었다. 두 가지가 틀렸다.

```
1  랠리의 끝을 검출하지 않는다
   "다음에 멈출 때까지" 를 통째로 랠리로 친다. 포인트가 끝나고 공 주우러
   가고 자리로 돌아오는 시간이 전부 랠리 안에 들어간다.
   → match_f 에서 랠리 사이 간격 중앙값이 4.0초로 나왔다. 실제 테니스는 20~25초다.

2  손으로 정한 임계값 하나로 판정한다   STILL_SPD = 0.55 m/s
   정지는 서브 전에만 일어나지 않는다. 볼 줍기 · 수건 · 물 · 코트 체인지 · 대화.
```

그리고 **성능을 측정한 적이 없다.** `SPEC.md` 가 요구한 `ground_truth.json` 이 없다.
"실제 서브 시점 3/3 일치" 가 전부인데 표본 3개다.

## 어떻게 만들 것인가

### 기준선 — RallyClip

https://github.com/iroblesrazzaq/RallyClip · 오픈소스 · 학습된 모델 포함

```
아키텍처   TennisPointLSTM · bidirectional · hidden 128 · 2 layers
입력       100프레임(20초) × 362 특징 · 5fps
특징       선수당 181개 × 2 (near / far)
             box · centroid · velocity · acceleration · speed
             키포인트 17개의 좌표·conf·속도·가속·속력 · 사지 길이 14
후처리     히스테리시스  low 0.45 / high 0.7 / min 1.0초
```

**공을 쓰지 않는다. 포즈만 쓴다.** 우리 병목이던 공 검출 71%를 통째로 우회한다.
**호모그래피도 필요 없다.** 특징이 전부 화면 좌표라 낮은 화각에서 코트 인식이
실패해도 걸리지 않는다.

### 여기서 배울 숫자 두 개

```
프레임 단위   accuracy 0.958   F1 0.925   AUROC 0.992
구간  단위   F1 0.674   precision 0.683   recall 0.675   mean_IoU 0.624
```

**프레임을 맞추는 건 쉽고 경계를 맞추는 게 어렵다.** 학습된 bi-LSTM에 362차원을
먹여도 구간 F1이 0.67이다. 이게 기준선이다.

### 우리 조건과 맞지 않는 부분

RallyClip 학습 데이터 11개 영상의 조건이 파일명에 박혀 있다.

```
angle   MED 4 · HIGH 7      ← LOW 가 없다
zoom    IN 4 · MED 4 · OUT 3
court   전부 하드코트
UTR     3 ~ 12
```

**낮은 화각 데이터가 없다.** 우리 촬영 조건이 정확히 빈 칸이다.

```
2  RallyClip 을 우리 영상에 그대로 돌린다

```

## 확인할 것

- **라이선스 파일이 RallyClip 레포에 없다.** README는 open source 라는데 `LICENSE` 가 없다.
  상업적으로 쓸 거면 저자 확인이 필요하다.
- 학습 데이터·라벨은 비공개다. 파인튜닝하려면 라벨은 우리가 찍어야 한다.
