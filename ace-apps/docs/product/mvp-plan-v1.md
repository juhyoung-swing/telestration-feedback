# 1. 문서의 역할과 운영 원칙

프로젝트 ACE는 앞으로 두 개의 문서를 별도로 유지·업데이트한다.

| **문서** | **역할** | **업데이트 기준** |
|---|---|---|
| 제품정의서 | 최종적으로 만들 전체 Sports Education OS의 제품 범위와 장기 방향 | 새로운 기능·사업모델·확장 방향이 추가될 때 |
| MVP 기획서 | 당장 1개월 동안 만들고 검증할 대상, 할 일, 담당자, 산출물과 일정 | MVP 범위·협업 방식·개발 우선순위가 바뀔 때 |

본 문서는 두 번째 문서인 MVP 기획서다. 전체 제품 비전은 유지하되, 1개월 동안 실제로 완성해야 할 업무를 세 개의 Workstream으로 나누어 정의한다.

# 2. 1개월 MVP 정의

## 2.1 대상 상품: Game Lesson Package

첫 MVP는 여러 기술과 레벨을 포괄하는 종합 커리큘럼이 아니다. 실제 경기력 향상을 원하는 성인 테니스 동호인을 위한 하나의 완결된 게임레슨 패키지로 한정한다.

> **제품 가설**
> 온라인에서 게임의 원리와 전술을 이해하고, 오프라인에서 동일한 커리큘럼으로 반복 훈련하며, 자신의 실제 수업 영상을 코치 피드백과 함께 복습하면 기존의 단발성 레슨보다 학습 효과와 재수강 의사가 높아진다.

## 2.2 MVP 기능 범위

| **영역** | **MVP에 포함** | **사용자 결과** | **MVP에서 제외** |
|---|---|---|---|
| 1. 온라인 강의 | 게임레슨 패키지의 개념·전술·드릴 강의 | 수업 전 예습, 수업 후 복습 | 다른 과정 전체, 구독형 콘텐츠 플랫폼 |
| 2. 오프라인 예약·결제 | 패키지 일정 확인, 예약, 결제, 수업 전후 자료 | 강의를 보고 바로 실제 수업 구매·참여 | 복잡한 다학원 SaaS, 수강권 조합, 정산 자동화 |
| 3. 수업 촬영·피드백 | 수업 영상 업로드, 핵심 장면, 코치 피드백 | 자신의 플레이를 근거로 복습 | 자동 샷분석, 자동 스코어링, AI 코치 |

## 2.3 MVP의 완결된 학습 흐름

1. 온라인에서 오늘 배울 게임 원리와 드릴을 본다.
2. 오프라인 게임레슨 패키지를 예약하고 결제한다.
3. 수업 전에 목표·진행순서·자가진단을 확인한다.
4. 코치가 동일한 커리큘럼으로 수업을 진행하고 촬영한다.
5. 수업 후 코치가 좋은 장면과 교정 장면을 선택해 피드백한다.
6. 학습자는 영상·복습자료·다음 과제를 확인한다.

# 3. 전체 실행구조: 세 개의 Workstream

MVP는 소프트웨어만 만드는 프로젝트가 아니다. 콘텐츠 IP가 먼저 존재해야 촬영할 수 있고, 촬영된 콘텐츠와 실제 수업 운영방식이 있어야 앱이 의미를 가진다.

| **Workstream** | **핵심 질문** | **주요 책임자** | **최종 산출물** |
|---|---|---|---|
| WS1. 커리큘럼·드릴 개발 | 무엇을 어떤 순서로 가르칠 것인가? | 김기준 대표 + 김형산 | 게임레슨 과정, 세션, 드릴, 코칭 기준 |
| WS2. 콘텐츠·수업자료 제작 | 그 지식을 어떻게 촬영하고 이해시키는가? | 김기준 대표 + Sub Coach + PD | 온라인 강의영상, 시범영상, 수업 전후 자료 |
| WS3. 소프트웨어·앱 | 고객과 코치가 어떻게 구매·수강·복습하는가? | 제품/개발팀 + 두 대표 | 관리자 웹, 코치 화면, 학습자 앱 MVP |

# 4. Workstream 1 — 커리큘럼·드릴·코스 개발

## 4.1 목적

김기준 대표의 머릿속에 축적된 경기 경험, 코칭 팁, 드릴과 판단기준을 반복 가능한 교육 IP로 구조화한다. 이 단계의 핵심 산출물은 영상이 아니라 “영상과 수업의 원본 설계도”다.

## 4.2 협업 방식: 세션별 6단계 반복

| **단계** | **작업 내용** |
|---|---|
| 1. 김기준 대표의 초안 | 해당 주제에서 학생이 반드시 알아야 할 원리, 자주 하는 실수, 대표 드릴, 코칭 팁을 말이나 메모로 자유롭게 풀어낸다. |
| 2. 김형산의 질문 + 해외 사례 리서치 | 모호한 개념, 순서, 적용 조건을 질문하고 RNA·Mouratoglou 등 해외 사례와 비교해 빠진 구조를 찾는다. |
| 3. 김형산의 1차 정리 | 초안을 학습목표, 개념, 드릴, 성공기준, 오류, 교정언어, 실전통합의 표준 템플릿으로 정리한다. |
| 4. 김기준 대표의 피드백 | 테니스적으로 틀리거나 현장에서 작동하지 않는 부분을 수정하고, 난이도와 코칭언어를 검수한다. |
| 5. 김형산의 최종 정리 | 피드백을 반영해 촬영 대본과 앱 콘텐츠에 바로 사용할 수 있는 최종본을 만든다. |
| 6. 다음 세션에 반복 | 게임레슨 패키지의 모든 세션에 동일한 프로세스를 반복한다. |

## 4.3 Game Lesson Package 구조 초안

정확한 세션 수와 주제는 김기준 대표와의 워크숍에서 확정한다. MVP에서는 4~6개 오프라인 세션과 이에 대응하는 온라인 강의 묶음을 권장한다.

| **세션** | **테마 예시** | **주요 내용** |
|---|---|---|
| Session 1 | 게임 진단과 확률 높은 플레이 | 현재 경기습관 진단, 실책 유형, 랠리 안정성 |
| Session 2 | 공간 만들기와 방향 선택 | 크로스·다운더라인, 상대 이동, 오픈코트 |
| Session 3 | 공격 전환과 마무리 | 짧은 공 판단, 어프로치, 네트 전환 |
| Session 4 | 수비와 중립화 | 깊이·높이·시간 확보, 포지션 회복 |
| Session 5 | 서브·리턴부터 시작하는 패턴 | 첫 2~3구 계획, 서브 후 위치, 리턴 방향 |
| Session 6 | 통합 매치플레이와 개인 처방 | 상황별 점수, 경기 영상 리뷰, 다음 훈련계획 |

## 4.4 세션별 필수 산출물

- 세션명과 한 문장 목표
- 대상 레벨과 전제 기술
- 왜 이 주제가 경기에서 중요한지
- 수업 전 온라인 강의의 핵심 개념
- 60분/90분/120분 수업 운영안
- 각 드릴의 목적·배치·진행방식·시간
- 드릴 성공기준과 난이도 조절법
- 자주 발생하는 오류와 교정언어
- 분석 포인트 플레이와 최종 통합 게임
- 수업 전 자가진단 질문
- 수업 후 복습 포인트와 개인과제
- 촬영할 시범 장면과 NG 예시

## 4.5 역할

| **담당** | **주요 역할** | **의사결정 권한** |
|---|---|---|
| 김기준 대표 | 테니스 철학, 기술·전술 원리, 드릴 원안, 현장 적합성 검수 | 테니스 내용의 최종 승인 |
| 김형산 | 질문 설계, 해외 사례 조사, 구조화, 문서화, 상품화 관점 정리 | 제품 구조와 고객 경험의 최종 정리 |
| AI 도구 | 회의 녹취 정리, 비교표, 초안 문서화, 표현 통일 | 결정권 없음; 두 대표의 판단을 보조 |

# 5. Workstream 2 — 영상 콘텐츠와 수업 전후 자료 제작

## 5.1 목적

WS1에서 확정된 커리큘럼을 고객이 이해할 수 있는 영상과 자료로 변환한다. 촬영의 목적은 “김기준 대표의 멋진 영상”이 아니라, 다른 코치도 동일한 수업을 운영하고 학습자가 예습·복습할 수 있게 만드는 것이다.

## 5.2 참여자와 역할

| **참여자** | **담당 업무** | **필수 기준** |
|---|---|---|
| 김기준 대표 | 메인 강의, 핵심 코칭 설명, 시범·교정, 최종 내용 검수 | 설명 언어와 동작 기준의 일관성 |
| Sub Coach | 피딩, 상대역, 학생역, 잘못된 동작과 올바른 동작 시연 | 반복 촬영이 가능하고 커리큘럼을 숙지 |
| PD/촬영팀 | 콘티, 촬영, 음향, 편집, 그래픽, 파일관리 | 교육적 이해가 쉬운 화면과 빠른 제작 |
| 김형산/기획 | 대본·자료 구조, 촬영 체크리스트, 앱 연결, 최종 사용자 관점 검수 | 수업 전후 경험과 영상의 연결 |

## 5.3 세션별 제작물

| **제작물** | **권장 길이** | **내용** |
|---|---|---|
| A. 온라인 개념강의 | 5~12분 | 전술의 원리, 판단기준, 경기 예시, 오늘 배울 내용 |
| B. 드릴 설명영상 | 1~3분/드릴 | 코트 배치, 피딩, 이동경로, 성공기준, 난이도 조절 |
| C. 시범·교정 클립 | 30초~2분 | 좋은 예·나쁜 예, 코치의 교정 포인트 |
| D. 수업 전 자료 | 모바일 1~2화면 | 목표, 진행순서, 사전영상, 자가진단, 준비물 |
| E. 코치 운영자료 | 1~3페이지 | 타임박스, 드릴 순서, 코칭 언어, 관찰항목 |
| F. 수업 후 자료 | 모바일 1~2화면 | 오늘의 핵심, 영상 하이라이트, 피드백, 숙제, 다음 수업 |

## 5.4 제작 프로세스

1. 커리큘럼 최종본 승인
2. 세션별 촬영대본·콘티 작성
3. 김기준 대표와 Sub Coach 리허설
4. 메인 설명·드릴·시범·오류장면 촬영
5. 1차 편집과 코트 그래픽 삽입
6. 테니스 내용 검수
7. 학습자 관점 검수
8. 앱 등록용 메타데이터와 썸네일 제작
9. 최종본 업로드 및 수업과 연결

## 5.5 RNA형 수업 전후 자료의 표준 템플릿

### 수업 전 자료

- 오늘의 테마와 한 문장 목표
- 이 상황이 실제 게임에서 발생하는 장면
- 핵심 판단기준 2~4개
- 수업 단계와 시간 배분
- 사전 온라인 강의
- 오늘 스스로 확인할 질문
- 준비물과 유의사항

### 수업 후 자료

- 실제로 진행한 드릴과 수업 요약
- 코치가 선택한 좋은 장면·교정 장면
- 잘한 점과 다음 개선점
- 개인별 과제
- 관련 복습 영상
- 다음 세션에서 이어질 내용

# 6. Workstream 3 — 소프트웨어·앱 제품

## 6.1 제품 목표

1개월 MVP의 소프트웨어는 범용 학원 SaaS가 아니라 Game Lesson Package를 판매하고 운영하기 위한 최소 제품이다. 기능은 온라인 강의, 오프라인 예약·결제, 수업 촬영·피드백의 세 흐름을 끊김 없이 연결하는 데 집중한다.

## 6.2 사용자 인터페이스

| **제품** | **주 사용자** | **MVP 목적** |
|---|---|---|
| 관리자 웹 | 운영자 | 패키지·세션·강사·일정·예약·결제·콘텐츠 관리 |
| 코치 모바일 웹/PWA | 김기준 대표 및 Sub Coach | 오늘 수업 확인, 출석, 영상 업로드, 학생별 피드백 |
| 학습자 앱/모바일 웹 | 패키지 구매자 | 강의 시청, 수업 예약·결제, 수업 전후 자료와 영상 확인 |

## 6.3 기능 범위 A — 온라인 강의

- Game Lesson Package 소개 및 커리큘럼 구성
- 세션별 온라인 강의 목록
- 강의 상세: 영상, 목표, 핵심 포인트, 코트 그래픽, 흔한 실수
- 수강완료 표시
- 관련 오프라인 세션 보기
- 강의에서 바로 수업 예약·결제로 이동
- 수업 후 관련 복습강의로 다시 연결

## 6.4 기능 범위 B — 오프라인 수업 예약·결제

- 패키지 및 세션 일정 조회
- 날짜·시간·장소·강사·잔여인원 확인
- 패키지 전체 구매 또는 MVP에서 정한 단일 결제방식
- 카드 결제 및 결제완료 확인
- 내 예약 목록
- 예약 변경·취소 요청
- 수업 전 자료와 알림
- 수업 완료 후 수업 후 자료 자동 노출
> **중요한 범위 수정**
> 이전 MVP 초안에서는 실시간 결제를 생략할 수 있다고 보았으나, 이번 MVP의 목적은 실제 Game Lesson Package 판매까지 검증하는 것이므로 최소 1개의 결제수단은 필수 범위로 포함한다.

## 6.5 기능 범위 C — 촬영과 강사 피드백

- 코치 또는 운영자가 수업 영상을 촬영·업로드
- 영상이 해당 수업 및 참가 학생과 연결
- 코치가 핵심 장면의 시작·종료 구간 선택
- 좋은 장면·교정 장면 분류
- 장면별 텍스트 또는 음성 코멘트
- 학생별 잘한 점·개선점·숙제 작성
- 관련 온라인 강의와 다음 수업 연결
- 학습자 앱에서 전체 영상 또는 지정 클립 확인

## 6.6 1개월에 하지 않는 기능

- 여러 종류의 커리큘럼과 전 레벨 과정
- 외부 학원 대상 범용 SaaS와 다지점 운영
- 게임·랠리 매칭 및 채팅
- 대회 운영
- Shop 및 용품 판매
- Coach Verified Level
- 자동 공·선수 추적, 샷분류, 스코어링
- AI가 직접 작성하는 코칭 피드백
- 일본어와 다른 스포츠

# 7. 1개월 통합 일정

세 Workstream은 순차적으로만 진행하지 않는다. WS1에서 한 세션이 승인되는 즉시 WS2 촬영 준비와 WS3 콘텐츠 입력을 병렬로 시작한다.

| **주차** | **WS1 커리큘럼** | **WS2 제작** | **WS3 제품** | **통합 검증** |
|---|---|---|---|---|
| Week 1 | 패키지 구조, 세션 1~2 확정 | 스타일·콘티·촬영환경 확정 | 화면·데이터·결제 설계 | 내부 사용자 흐름 리뷰 |
| Week 2 | 세션 3~6 초안·검수 | 세션 1~2 촬영·1차 편집 | 강의·패키지·예약·결제 구현 | 첫 콘텐츠 앱 등록 |
| Week 3 | 전체 커리큘럼 최종 | 나머지 세션 촬영·편집 | 수업 전후·영상·피드백 구현 | 파일럿 수업 1차 |
| Week 4 | 현장 피드백 반영 | 수정촬영·최종 납품 | 통합 QA·알림·운영화면 | 유료 베타 운영·회고 |

# 8. 산출물 체크리스트

## WS1 완료조건

- ☐ Game Lesson Package의 대상·약속·세션 수 확정
- ☐ 각 세션의 목표와 시간표 확정
- ☐ 모든 드릴의 목적·진행·성공기준·오류·교정언어 확정
- ☐ 수업 전후 자료와 촬영 대본 작성 가능 상태
- ☐ 김기준 대표의 최종 테니스 검수 완료

## WS2 완료조건

- ☐ 각 세션 온라인 강의 최종본
- ☐ 각 드릴 설명·시범 영상
- ☐ 모바일용 수업 전 자료
- ☐ 코치용 운영자료
- ☐ 모바일용 수업 후 자료 템플릿
- ☐ 파일명·썸네일·메타데이터 정리

## WS3 완료조건

- ☐ 사용자가 패키지를 보고 결제할 수 있음
- ☐ 강의를 보고 관련 수업을 예약할 수 있음
- ☐ 수업 전에 자료가 노출됨
- ☐ 코치가 영상과 피드백을 등록할 수 있음
- ☐ 학생이 수업 후 영상·피드백·숙제를 확인할 수 있음
- ☐ 관리자가 예약·결제·출석·콘텐츠를 관리할 수 있음

# 10. MVP 성공기준

1개월 MVP는 기능 개수보다 하나의 유료 패키지가 실제로 작동하는지를 평가한다.

| **영역** | **검증 지표** |
|---|---|
| 콘텐츠 | 수업 전 온라인 강의 시청률, 수업 후 복습률 |
| 판매 | 패키지 상세 → 결제 전환율, 환불·취소율 |
| 운영 | 예약 오류율, 출석 처리시간, 영상·피드백 등록시간 |
| 학습 | 수업 후 영상 열람률, 피드백 열람률, 숙제 수행률 |
| 고객 | 다음 패키지 또는 추가수업 구매의향, 추천의향 |
| 코치 | 커리큘럼이 실제 수업을 더 쉽게 만들었는지, 피드백 업무가 감당 가능한지 |
