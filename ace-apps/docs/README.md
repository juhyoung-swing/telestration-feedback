# docs — 사업·제품 문서

**코드가 아니라 결정이 들어간다.** 무엇을 만들지 정하는 문서만 여기 둔다.
기능이 어떻게 동작하는지는 각 기능 폴더의 `README.md` 가 갖는다.

```
docs/
  roadmap/     사업 단계 — Phase 와 검증 조건
  product/     제품 범위 — 전체 정의서 · 현재 MVP
    screens/   지금 만들 화면 — 제품별 목업 명세
  research/    경쟁·사례 리서치
  team/         합류한 사람이 먼저 읽는 것
  _source/     원본 docx + 변환 스크립트
```

## 문서 사이에 아직 안 맞는 것

> 아래는 문서에 적힌 내용이 아니라 **문서를 나란히 놓고 대조한 결과**다.
> 정하는 사람이 결정하면 해당 문서를 고치고 이 절을 지운다.

### 1. AI 범위 — 로드맵은 넣고, 7월 문서 둘은 뺐다

로드맵(최신)의 Phase 1 은 AI 기능을 MVP 안에 넣는다.

```
레슨 영상 AI 자동편집 · 주요 장면 추출 · Score · Rally · Shot Count · 속도
```

그런데 7월 문서 둘은 명시적으로 제외한다.

| 문서 | 해당 절 | 제외한 것 |
|---|---|---|
| MVP 기획서 | §2.2 · §6.6 | 자동 샷분석, **자동 스코어링**, 자동 공·선수 추적, AI 코치 |
| 온보딩 가이드 | §5 | SwingVision 수준의 **고급** 자동 샷 분석·자동 스코어링 |

온보딩 가이드는 "고급" 이라는 한정어가 붙어 기본 AI 는 열어뒀다고 읽을 수 있지만,
MVP 기획서의 "자동 스코어링" 제외와 로드맵의 "Score Count" 포함은 **정면으로 부딪힌다.**

**이게 중요한 이유** — 판정에 따라 저장소 최상단의 파이썬 기능 9개가
연구용에서 **Phase 1 납품물로 신분이 바뀐다.**

### 2. 촬영 조건 — 속도와 Score 는 낮은 화각에서 측정 불가로 이미 판정났다

로드맵이 Phase 1 에 넣은 항목을 저장소의 실측치와 대조하면 이렇다.
근거는 [ace-poc README](../../ace-poc/README.md) 의 `rally ↔ match` 절이다.

| 로드맵 Phase 1 항목 | 담당 기능 | 상태 | 낮은 화각에서 |
|---|---|---|---|
| 레슨 영상 AI 자동편집 | `video-transcribe` → `video-directive` → `video-edit` | 됨 | 무관 |
| 주요 장면 추출 | `lecture-shortform` | **데모만** | 무관 |
| Rally Count | `rally-detect` | **코드 없음** (설계만) | 된다 — 포즈만 씀 |
| Shot Count | `match-analysis` | 됨 | 코트 좌표 필요 |
| **속도** | `match-analysis` | 됨 | **안 된다** |
| **Score** | `match-analysis` | **안 되는 것으로 분류** | **안 된다** |

```
낮은 화각   코트가 화면 세로의 13%    재투영 오차 92.8 cm   코트 좌표 불가
높은 화각   54 ~ 70%                 5.1 ~ 6.7 cm         코트 좌표 가능
```

**대부분의 유저는 폰을 거치해서 낮은 화각으로 찍는다.** 속도·Score·인아웃은
코트 좌표계가 성립해야 나오는 값이라 그 조건에서는 원리적으로 안 나온다.

따라서 Phase 1 에서 이 둘은 셋 중 하나여야 한다.

```
1  촬영 조건을 제품이 강제한다        "높은 곳에 거치" 를 요구사항으로 올린다
2  Phase 3 으로 미룬다               MVP 에서는 랠리·샷 카운트까지만
3  높은 화각 전용 기능으로 격리한다     경기 영상에만 켜지는 기능
```

### 3. 일정 — "1개월" 과 "10월까지" 가 다르다

```
MVP 기획서   2026-07-22 기준 1개월  →  2026-08 말
사업 로드맵   Phase 1               →  2026-10
오늘         2026-08-19
```

로드맵이 더 나중에 합의됐으므로 **10월이 유효한 기한**으로 보이지만,
MVP 기획서의 4주 일정표(§7)는 그대로 남아 있다. 기획서의 주차 표를 다시 끊어야 한다.

### 4. `apps/` 는 아직 코드가 없다

`docs/` 는 제품 3개(관리자 웹 · 코치 앱 · 학습자 앱)를 정의하지만
[apps/](../apps/README.md) 에는 아직 코드가 없다. 무엇이 들어갈 예정인지는 그쪽 README 에 적었다.

## 변환에 대해

`_source/` 의 docx 가 원본이다. `.md` 는 `_source/docx2md.py` 로 변환한 것이고,
제목·bold·번호목록·표·강조박스·하이퍼링크만 옮긴다. **원본을 고친 뒤에는 다시 변환한다.**

```bash
python3 docs/_source/docx2md.py docs/_source/<파일>.docx
```

문서 앞의 인용 블록(출처·작성일)은 변환기가 만들지 않는다. 사람이 붙인 머리말이라
재변환할 때 다시 얹어야 한다.
